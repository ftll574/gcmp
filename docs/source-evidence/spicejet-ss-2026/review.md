That existing schema carries route + exact flight-number reference without weekday or time fields; the route UI reports reference-only timing as unknown. Keep this ledger as the authoritative exact validity and variant snapshot. The companion `official-schedules.patch.json` supplies the `sources` and `flightNumberReferences` sections as a merge-ready fragment; it has not been applied to the canonical checkout. Do not populate `OfficialService.daysOfWeek`, `departureTime`, `arrivalTime`, or actual-operation fields from this packet.

The reference schema does **not** encode each flight's effective date range; its `reviewBy` is source freshness, not a date-of-travel gate. So references are safe as designator/source hints with unknown schedule status, but cannot prove a flight is scheduled for a chosen date. For date-specific availability, add a date-window-aware evidence model or an explicit selection gate before exposing these references as dated services. Exclude the five expired-only keys. If route-network browsing is also needed, admit only source-backed directed pairs whose endpoints are in the airport catalog; keep route evidence separate from actual-operation evidence.
