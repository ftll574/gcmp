# GCMP 第一批修復紀錄

日期：2026-09-05。接續 `docs/takeover-audit-2026-09-05.md`；使用者已明確要求開始優化與修正。

## 決策與範圍

沿用 React／TypeScript／SVG 與靜態 JSON，不增加後端或依賴。先修行程資料可信度、必要接線與操作入口；不是宣稱完整航網或即時獎勵座位已可查詢。

**營運航空是使用者的航班資料；兌換方案是檢查這些資料的規則，不是改寫航班的命令。** 匯入或切換方案不再自動替換營運航空。不相容航空保留在選單中並標示問題，規則面板列出航段編號、機場與航空代碼。

## 已實作

1. 將原盤點的八項失敗探針提升為永久整合測試（`tests/components/App.planning-integrity.test.tsx`），並修正對應行為：清除單一欄位不再刪除日期或其他 metadata；刪站／重排按「原機場出現位置」保留未改變航段，重複機場對也不會偷用另一段日期；營運航空不再被自動重寫；探索器新增帶回指定航空；班表接入主驗證。
2. 修正清空行程後的 hash 導航旗標，避免下一個分享連結／返回事件被吞掉。
3. 航空選單使用現有聯盟目錄補足舊航空主檔的缺項：原本漏出的 23 個成員代碼可選，名稱來自原目錄。**沒有杜撰國家或 ICAO，也未宣稱重新查核全球聯盟成員資格。** 新增跨目錄一致性測試。
4. 方案／艙等設定和逐段日期預設展開；逐段日期放在探索器之前；空白行程範例移至主要編輯區。新行程不再出現舊累積哩程用的訂位代碼選單；帶有舊代碼的分享行程仍保留相容編輯。
5. 規則面板分成空白、違規、待補資料、需確認警告、規則通過。尚缺出發日期或有 unknown finding 的行程不再顯示綠色通過。另明示：沒有查實際航班／獎勵座位，報價不含稅費。
6. 探索器增加「資料涵蓋日期」與來源／有效期；過期或未來窗口會提示重新查證，但仍允許手動規劃，不把缺資料誤判為停飛。新增航段後解除舊起點覆寫，讓下一步跟隨新終點。逐段班表註記改看該段選定日期，不再永遠看今天。
7. 舊累積哩程 program JSON 全部載入失敗時，不再連帶讓獨立 RTW 規劃器無法啟動；它們目前仍會被請求，尚未做按需載入。
8. 768–1279px 視窗將規則面板移至地圖下方，避免原三欄最小寬度擠出畫面。保留既有手機範圍限制，沒有宣稱完成手機拖曳編輯。

## Qantas 報價更正與版本保留

官方來源：`https://www.qantas.com/en-us/frequent-flyer/use-points/classic-flight-rewards/tables`，2026-09-05 查核其 **oneworld Classic Flight Reward** 表，不是其他 Partner／Qantas 表。

- 現行新訂位資料補為 10 個距離級距 × 4 種艙等；19,201–35,000 英里商務艙為 **365,800 Qantas Points**。
- `bookingEffectiveFrom=2025-08-05`、`verifiedOn=2026-09-05` 記在該產品上。沒有把其他未重新查核表格的日期一起改新。
- `currency` 支援 points，Qantas 主報價以點數呈現。
- 原本部分歷史表凍結於 `tests/fixtures/qantas-pre-2025-08-05.json`，原 318,000 點、部分艙等缺價等歷史斷言仍然保留；現行表另有 12 項測試涵蓋全部價格與區間邊界。
- **訂位日決定表格年代，不是出發日。** 規劃器目前明確做新訂位估算，沒有舊票改票計價模式，也不會由分享 URL 重建原來開票價格。既有 v1 URL 格式不變。
